# 界面

两张卡，面向两种时刻：

| 卡 | 面向 | 内容 |
|---|---|---|
| **工作台** | **验收者**——「这版做得怎么样」 | run 列表、主图、产物清单、标基线、写意见、**设置** |
| **控制台** | **操作者**——「手上还有活要干」 | 冷启动五步进度、服务起停、bpy 执行、通道与体检 |

主界面按**结果**优先设计。理由：这个 App 里主要甚至全部工作都由 agent 完成，人要做的是**看结果、下判断**，不是操作面板。所以工作台是默认的那张。

## 设置为什么不放宿主的设置页

它曾经挂在那边（`contributes.settings` → 独立一页）。搬进卡片的理由不是"少一次跳转"，而是**归属**：「装了什么 addon、往哪投、归档怎么清、怎么装」是**用这个 App 时随时要看的**，不是安装时看一眼就再也不碰的东西。散在宿主总设置里，人根本不会去那里找。

（搬的时候顺手把 `panel.css` 剪干净了：它原先是那独立页的样式表，里面还留着上一代「控制台」页的残留，以及三个会和 workbench 抢同名类的规则——`.shell` / `.mono` / `.dot`。细节见该文件头部注释。）

## 写意见

run 详情里有自由输入框，不只有「采用 / 回退 / 再改一版」三个按钮——**只给选项等于把话堵死，人想说的常常不在选项里**。写下的话存在本地，切走再回来还在，回会话里说一声 agent 就照着改。

## 主题跟随

界面颜色从宿主主题读，不写死。宿主不注入主题时**如实标「兜底色板」**，不假装跟随成功。
